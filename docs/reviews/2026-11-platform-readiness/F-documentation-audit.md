# F. Documentation Audit

## 1. Verdict

The documentation is unusually well **gated** and poorly **aimed**. Links, path citations, the ADR index, the manifest reference, the platform contract tables and the system-map counts are all generated or checked in CI. The pages a newcomer reads first are the ones no gate covers, and they have drifted.

## 2. Inventory

673 tracked files under `docs/`. 642 Markdown files repo-wide were link-checked.

| Group | Count | State |
|---|---|---|
| ADRs (`docs/architecture-decisions/`) | 120 | Governed by `check:adr`. 83 Implemented, 22 Accepted, 10 Proposed, 4 Superseded, 1 Deferred |
| PDRs (`docs/product-decisions/`) | 12 | Governed |
| Generated API reference (`docs/api/`) | about 400 files | Generated by TypeDoc, gated |
| Generated references | `spec.md` index, `docs/schemas/manifest-fields.md`, `PLATFORM-CONTRACT.md` tables, `system-map.html` counts | Gated |
| Top-level guides and explainers | about 40 `.md`, 8 `.html` | Hand-maintained, mixed currency |
| Requirements and acceptance criteria | 10 + 7 | Pre-oclif era. Currency **not evaluated** |
| Archive | `docs/archive/` | Clearly labelled |
| Agent instructions | `CLAUDE.md`, `docs/DEVIN.md`, `.github/copilot-instructions.md`, `.copilot/`, `.agents/` | Three parallel instruction sets for three tools |
| Package and example READMEs | `packages/README.md` (tested against disk), per-example READMEs | Good where sampled |

**Missing entirely:** `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, a CLI reference, a configuration and environment-variable reference, a troubleshooting guide, an upgrade guide, a deployment and operations guide for the control plane.

## 3. Accuracy findings

### DOC-01 · README covers under half the product

- **Fact.** The README's command section lists `remote:*`, `build:*`, `bff:*`, `api`, `deploy` and `plugins`. It does not mention `mfe:validate`, `compose:*`, `slots:validate`, `decompose:*`, `flow:status`, `sentinel:validate`, `design:export`, `adr:*`, `coder:compile` or `schemas`.
- **Fact.** It gives about 80 lines to how the GitHub Pages site is assembled and deployed. That is maintainer material.
- **Fix.** Generate the command table from `oclif.manifest.json` (`oclif readme` does this). Move the Pages section to a contributor doc.

### DOC-02 · The docs index is not an index

- **Fact.** `docs/README.md` is titled "Agent System — seans-mfe-tool". Most of its 363 lines describe Copilot agents and cite files such as `requirements-elicitation-agent.md` that are not in `docs/`.
- **Fix.** Replace it with a real index following the structure in section 5.

### DOC-03 · Project status carries a stale count

- **Fact.** `docs/PROJECT-STATUS.md:105` says "79 ADRs: 52 Implemented, 14 Accepted, 11 Proposed". The directory has 120.
- **Note.** The page itself warns that it is hand-maintained and has drifted before.
- **Fix.** Delete the sentence and link the generated index, or generate it.

### DOC-04 · Getting started cannot be completed by an adopter

- **Fact.** It begins from a clone and `npm run build`. It states Node ≥18. `package.json` requires ≥20.
- **Inference.** Step 4 (`npm install` in the new MFE) cannot resolve `@seans-mfe-tool/runtime` outside the repository (ARC-01).
- **Fact.** Step 6 tells the reader to run `bff:init` after adding a `data:` section. The manifest schema says the presence of `data:` is what makes the generator emit a BFF. The two paths are not reconciled for the reader.
- **Fact.** The troubleshooting pointer goes to a file under `docs/archive/`.

### DOC-05 · Overlapping architecture documents

Ten top-level documents describe the architecture, with no stated precedence:

`architecture-current-state.md` (860 lines), `architecture-whitepaper.md` (953), `architecture-runtime-platform.md`, `platform-architecture-brief.md`, `platform-architecture-comparison.md`, `architecture-composition-primer.md`, `lifecycle-engine-analysis.md` (1,058), `runtime-class-hierarchy.md`, `architecture-codegen.md`, `architecture-dsl.md`, plus four HTML explainers.

Plans sit beside reference material: `MERGE-PLAN.md` (opens by saying half of it is void), `RESTRUCTURE-PLAN.md` (dated July), `generator-extraction-plan.md` (1,005 lines), `bff-refactor-analysis.md`, `gate-self-verification-audit.md`.

## 5. Proposed information architecture

One tree. Each page has one job. "Generated" means produced by a script and gated.

```
docs/
  index.md                     1. Overview and core concepts (the four-concept model)
  quickstart.md                2. Install to running MFE, from npm, tested in CI
  tutorials/                   3. Common workflows
    add-data-bff.md
    compose-a-fleet.md
    second-framework.md
    decompose-a-monolith.md      (labs)
  reference/
    cli.md                     4. Generated from the oclif manifest
    manifest.md                   Generated (exists: docs/schemas/manifest-fields.md)
    platform-contract.md       5. Generated (exists)
    configuration.md           7. Environment variables, files, precedence
    api/                          Generated (exists)
  architecture/
    overview.md                5. ONE current-state document
    codegen.md, dsl.md, runtime.md, composition.md, slots.md
  extending/
    command-plugins.md         6. (exists: PLUGIN-CONTRACT.md)
    framework-plugins.md          (exists)
    native-targets.md             (exists)
  operations/
    control-plane.md           7. Deploy, configure, health
    security.md                8. Trust model, hardening
    observability.md              (ADR-081 in user terms)
  troubleshooting.md           9.
  contributing/
    index.md                  10. Gates, release process, docs site
    decisions/                    ADRs and PDRs
  labs/                           Decomposition, design export, coder
  archive/                        Plans carried out or voided
```

Root files: `README.md` (short: what, install, first command, link to docs), `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`.

## 7. Gate to add

A **quick-start smoke test**: CI extracts the fenced commands from `quickstart.md`, runs them in a clean container against the packed CLI, and fails if any step fails. This is the one documentation gate the repository lacks, and it is the one that protects the first impression.
