# ADR-084: Generation targets the manifest, not source — the intent→manifest step is the one stochastic seam

## Context

Codegen today is a deterministic function of the manifest. `mfe-manifest.yaml` →
`packages/codegen/src/unified-generator.ts` (`generateAllFiles`) → EJS templates →
files tagged `overwrite: true|false`, and `scripts/check-mfe-drift.ts` regenerates
every `examples/**` MFE and fails CI on any generator-owned byte that differs. That
reproducibility is the platform's central guarantee (PDR-001, ADR-043): a human can
audit the manifest and trust the code follows from it.

PDR-009 moves the authoring surface upstream to a business intent compiled by a model.
The question this ADR settles is *where the model's output lands*. If the model writes
source, generated bytes stop being a function of the manifest: `check:mfe-drift` has
nothing stable to diff against, and the `overwrite: true`/`false` ownership seam
(`unified-generator.ts`, ADR-082) loses meaning. The invariant the whole platform
rests on would be the first casualty of going generative.

## Decision

Generation targets the DSL, and only the DSL.

### 1. The model emits a validated manifest, never source

The output of intent-compilation is an `mfe-manifest.yaml` (and, for composition, a
`control-plane.yaml`) — the same DSL a human authors. It is not code, not a template,
not a generator-owned file.

### 2. The manifest→code step is unchanged and sole-owner

`unified-generator.ts` remains the only thing that writes generator-owned
(`overwrite: true`) files, deterministically, from the manifest. The generative path
adds a step *before* it and changes nothing *at or after* it. Composition continues to
compile through `deriveRegistration` / `compileControlPlane` (ADR-074, ADR-083) with
no new authoring of `rules.json`.

### 3. CI is the acceptance oracle; generation fails closed

A generated manifest is accepted only when it passes what a hand-written one must:
`parseAndValidateDirectory`, then the fleet gates — `check:mfe-drift:check`,
`compose:validate --check`, `slots:validate`, `check:mfe-consistency`. Stochastic
output that violates the contract is rejected by the same gates that catch a human's
mistake, so a bad generation never reaches a running shell.

## Boundaries

- This ADR does **not** touch the `overwrite:true/false` seam, the templates, or the
  runtime contract — it constrains only what a *generator* is allowed to produce.
- It does **not** itself sanction model authorship of developer-owned feature files (the
  `overwrite:false` side codegen seeds once and never rewrites). That lane is taken up
  separately by ADR-087, which lets coder's source adaptor fill it — a different
  decision, because those files are the ones the drift gate never compares.
- It does **not** specify *how* intent is compiled or *what model* runs — that is
  ADR-085. It fixes only the target of generation.

## Consequences

- **Better:** reproducibility is preserved end to end; the existing validation surface
  becomes the safety net for AI output at zero new gate cost; humans keep auditing the
  same manifest boundary PDR-003 established.
- **Worse / the cost accepted:** anything the DSL cannot express, the model cannot
  generate. Expressiveness pressure moves onto `packages/dsl/src/schema.ts`, and the
  temptation to "just let the model write the file" for a gap the DSL can't yet model
  has to be resisted or answered with a DSL extension.
