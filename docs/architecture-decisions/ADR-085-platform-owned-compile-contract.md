## Context

`tsconfig.json` is emitted `overwrite: false` — seeded once, never touched
again. The intent was sound: an MFE author edits compiler config as a matter of
course. The result was not.

Surveying the 21 example MFEs:

- **1 of 22** tsconfigs matches the template it was generated from.
- The template declares `module: commonjs` / `moduleResolution: node`. **14
  MFEs declare `module: ESNext` / `moduleResolution: bundler`** — they were
  seeded from an older template and froze there, so the fleet runs a
  configuration the platform no longer emits.
- **14 carry `paths` mapping `@falese/smt-runtime` to
  `../../../src/runtime/index.ts`**, a directory that moved to
  `packages/runtime` long ago. Dead mappings nothing reports.
- `meridian-console` uses `moduleResolution: node` while having no BFF —
  inconsistent with all 14 of its browser-only peers, and nothing noticed.

The divergence is not arbitrary, which is the important part. It tracks one
fact almost perfectly:

| Shape | `moduleResolution` | Count |
|---|---|---|
| Has a BFF (a Node `server.ts`) | `node` / commonjs | 8 of 8 |
| Browser-only | `bundler` / ESNext | 14 of 15 |

That is a *platform* distinction — the same `data:` manifest section that
already drives BFF dependencies, the Dockerfile and federation `shared`. The
fleet worked out the right answer per shape and then had no way to say so,
because the file expressing it is one the platform may not touch.

ADR-084 made this concrete: moving the runtime's compiled output under `dist/`
broke every generated MFE's compile, and the fix could not be delivered through
`tsconfig.json` because regeneration cannot reach it. Root-level Node10
forwarders were shipped instead — a workaround for a setting the platform
should have been able to change.

## Decision

### 1. Split the file along the ownership line

A generated React MFE gets **two** files:

- **`tsconfig.platform.json`** — generator-owned (`overwrite: true`). Carries
  only the settings the platform's *own emitted code* needs in order to
  compile: `target`, `module`, `moduleResolution`, `jsx`, `lib`,
  `esModuleInterop`, `strict`, `skipLibCheck`, `resolveJsonModule`,
  `forceConsistentCasingInFileNames`.
- **`tsconfig.json`** — unchanged ownership (`overwrite: false`). Now
  `extends: "./tsconfig.platform.json"` and holds what genuinely varies per
  project: `include`, `exclude`, `baseUrl`/`paths`, `outDir`, and any
  `compilerOptions` the author wants to override.

The relationship is inheritance, and deliberately so: it is the same shape as
`BaseMFE`. The platform states the contract in a base the developer does not
edit; the developer specialises it in a file the platform never clobbers.
Overriding is legal — `extends` is a merge, not a seal — so an author who needs
a different `module` can still set one, visibly, in their own file.

### 2. The compile contract is derived, not templated

`module`/`moduleResolution` follow the manifest's `data:` section, matching
what the fleet arrived at independently:

- **BFF present** → `commonjs` / `node`, because `server.ts` runs in Node.
- **Browser-only** → `esnext` / `bundler`, because rspack resolves, and
  `bundler` reads the `exports` map that ADR-084's packages publish.

### 3. Regeneration is the delivery mechanism

Because the platform file is `overwrite: true`, it comes under
`check:mfe-drift` — the only gate that compares generated bytes. A compiler
setting the platform needs can now be changed once and regenerated, instead of
being worked around.

## Boundaries

**Angular is out of scope.** The Angular variant already carries a multi-file
split (`tsconfig.json`, `tsconfig.app.json`, `tsconfig.spec.json`) with
Angular-specific options and a documented constraint that the *root* module
must stay `commonjs` because GraphQL Mesh derives its artifact module system
from it. Folding that into a shared platform base needs its own analysis; doing
it blind would risk the Mesh artifacts. React MFEs — BFF and browser-only
alike — are covered here.

This does **not** flip `tsconfig.json` to generator-owned. That would be the
most breaking edit the generator can make, and it would destroy real work: the
`.mesh` and test `exclude` entries, and local `paths`. Nothing an author has
written is overwritten by this decision.

It does not typecheck anything new. BFF MFEs restrict `include` to `*.ts`,
which means their `.tsx` React components are not typechecked at all today.
That is a real gap, and a separate one.

## Consequences

The platform can change a compiler setting and have it arrive, which it could
not do before — the immediate payoff being that ADR-084's `bundler` resolution
reaches browser-only MFEs rather than depending on root-level forwarders for
correctness. Fleet-wide inconsistency (`meridian-console`) and dead `paths`
stop being invisible, because the derived half is now byte-compared.

The cost: every existing MFE needs one line added — `extends` — and being
developer-owned, regeneration cannot add it. That is a `PLATFORM_MIGRATIONS`
entry under ADR-082, detectable by the absence of the extends, and it is the
second time this change has paid that particular tax. It is the honest price of
not clobbering author-owned files.

A second cost worth naming: two files where there was one. An author now has to
know which to edit. The generated header in each says so, and `extends` is a
convention TypeScript developers already read.
